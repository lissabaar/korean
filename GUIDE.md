# Путеводитель по проекту

Здесь описано, как устроено приложение: какие в нём технологии, как работает
Next.js, какой путь проходят данные и какой файл за что отвечает. Рассчитано
на человека, который умеет программировать, но с Next.js и React знаком мало.

Другие документы:
- [SETUP.md](SETUP.md) — как запустить проект на новом компьютере;
- [VERCEL.md](VERCEL.md) — выкладка на сайт;
- [PRICING.md](PRICING.md) и [PAYMENTS.md](PAYMENTS.md) — тарифы и оплата;
- [CLAUDE.md](CLAUDE.md) — правила проекта для меня (Стефании), на английском.
  Там же перечислены решения, которые уже приняты, и почему.

В каждом файле в `src/` в самом начале есть комментарий о том, что это за
файл. Над каждой функцией написано, что она делает. Комментарии в коде на
английском: так принято в коде, и репозиторий публичный.

## 1. Что делает приложение — в одном абзаце

Ты даёшь корейский текст, скриншот, колоду Anki/ReWord или тему («слова про
погоду»). Модель Claude находит в нём слова и приводит их к словарной форме
(먹었어요 → 먹다), а заодно предлагает категорию. Каждое слово проверяется по
корейскому словарю KRDict: оттуда берутся перевод, определение, уровень, ханча
и примеры. Из слов получаются карточки. Сначала слово заучивается («Learn»: пока
не ответишь правильно N раз подряд), потом повторяется по расписанию
интервального повторения FSRS («Review»).

## 3. Next.js за пять минут

### Папки — это адреса

В «App Router» (`src/app/`) путь к файлу совпадает с адресом на сайте:

| Файл | Адрес | Что это |
|---|---|---|
| `src/app/(app)/page.tsx` | `/` | главная |
| `src/app/(app)/settings/page.tsx` | `/settings` | страница настроек |
| `src/app/api/review/answer/route.ts` | `/api/review/answer` | API-маршрут, то есть адрес, на который браузер шлёт данные |
| `src/app/api/words/[id]/route.ts` | `/api/words/abc123` | `[id]` — переменная часть адреса |
| `src/app/api/auth/[...all]/route.ts` | `/api/auth/что-угодно` | `[...all]` — «всё, что дальше» |

Специальные имена файлов:

- **`page.tsx`** — страница. Функция, которую файл экспортирует по умолчанию,
  возвращает разметку.
- **`layout.tsx`** — обёртка вокруг всех страниц в этой папке и вложенных
  в неё (общая шапка, навигация).
- **`route.ts`** — API. Функции с именами `GET`, `POST`, `PATCH`, `DELETE`
  обрабатывают соответствующие HTTP-методы и возвращают JSON.

Папка в скобках, например `(app)`, — это **группа маршрутов**. Она объединяет
страницы под одним `layout.tsx`, но в адрес не попадает: `(app)/add/page.tsx`
открывается как `/add`, без `/app`.

### Серверные и клиентские компоненты — главное, что нужно понять

**Серверный компонент** — все страницы и layout'ы в этом проекте. Код
выполняется на сервере при каждом запросе. Он может напрямую читать базу
(`await prisma...`) и знает секретные ключи. Браузер получает уже готовый HTML,
сам код к нему не попадает.

**Клиентский компонент** — файл начинается со строки `"use client"`. Это всё
в `src/components/`. Код выполняется в браузере. Он может хранить состояние
(`useState`), реагировать на клики и вызывать API через `fetch("/api/...")`.
А вот трогать базу и ключи не может, потому что браузер чужой.

Типичная связка в проекте:

```
settings/page.tsx  (сервер)   читает из базы настройки и счётчики
        │  передаёт их как свойства (props)
        ▼
SettingsPanel.tsx  (браузер)  показывает переключатели; по клику
        │                     делает fetch("/api/settings", PATCH)
        ▼
api/settings/route.ts (сервер) проверяет данные и пишет в базу
```

### Мелочи, которые встречаются в коде

- `export const metadata = { title: ... }` — заголовок вкладки браузера.
- `export const maxDuration = 300` — сколько секунд Vercel разрешает
  выполняться этому маршруту. 300 — максимум на бесплатном тарифе.
- `params` и `searchParams` в этой версии Next.js — это Promise, поэтому
  `await params`.
- `router.refresh()` в клиентском компоненте заново запрашивает у сервера
  данные страницы, не перезагружая её целиком.
- `import ... from "@/lib/db"`: `@/` означает папку `src/` (так настроено
  в `tsconfig.json`).
- Хуки React: `useState` — переменная, при изменении которой экран
  перерисовывается; `useEffect` — код, который запускается после отрисовки
  (например, загрузить данные); `useRef` — ссылка на элемент или значение
  без перерисовки.

## 4. Как бегут данные

```
 Браузер (React, src/components)
   │  fetch("/api/...")                 ▲ JSON
   ▼                                    │
 API-маршрут (src/app/api/**/route.ts) — проверяет, кто ты и что прислали
   │  вызывает функцию из
   ▼
 Логика (src/lib/**) ──► Prisma ──► PostgreSQL (Neon)
   ├──► Anthropic (Claude)       — только через ai-budget.ts (счётчик денег)
   └──► KRDict                   — только через dictionary/cached.ts (общий кэш)
```

Маршруты в `src/app/api` нарочно тонкие: проверили вход, вызвали функцию из
`src/lib`, превратили ошибку в HTTP-код. Вся логика живёт в `src/lib`.

### Сценарий 1. Добавление слов (`/add`)

1. **Чтение в браузере** (`lib/import/read.ts`, `anki.ts`, `reword.ts`).
   Файл разбирается прямо на твоём компьютере. На сервер уходит только текст
   или уменьшенная картинка; медиа из колоды Anki никуда не отправляются.
   Большой текст режется на части по 40 строк.
2. **Анализ** — `POST /api/ingest/analyze` для каждой части, по три
   одновременно (`AddWords.tsx` → `runJobs`). На сервере:
   - `ai-budget.ts` проверяет, хватает ли кредитов;
   - `ingest/extract.ts` спрашивает модель: какие тут слова, в какой
     словарной форме, какой категории, какое у каждого краткое значение (gloss);
   - расход записывается сразу после ответа (`recordAiUsage`);
   - `ingest/analyze.ts` ищет каждое слово в словаре и выбирает нужный омоним
     (공원 — парк или рабочий?) по значению от модели.
   В результате получаются «кандидаты» со статусами: новое, уже есть, есть
   только значение от ИИ, словарь не ответил.
3. **Сохранение** — `POST /api/ingest/commit` → `ingest/commit.ts`. Создаются
   слово (`Entry`), его значение (`Sense`), примеры, категории и карточки
   (`Card`). В режиме «Add automatically» каждая часть сохраняется сразу после
   анализа.
4. **Доделка в фоне**:
   - слова, на которые словарь не ответил, перепроверяются (`/api/verify`);
   - где нет английского значения, оно дописывается (`/api/meanings`);
   - где нет примера, он добавляется (`/api/examples`);
   - примеры переводятся (`/api/translations`).

### Сценарий 2. Учёба (`/learn`, `/review`)

1. `GET /api/review/session` → `review/queue.ts` собирает карточки сессии
   и для каждой решает, что спросить.
2. `Review.tsx` перемешивает их и показывает по одной:
   - **знакомство** — новое слово сначала показывается целиком, с кнопками
     «Start learning» и «Skip for 3 days» (`/api/review/intro` →
     `review/intro.ts`);
   - **вопрос** — выбрать из вариантов (CHOICE) или напечатать (TYPING).
     Неправильные варианты подбирает `review/distractors.ts`.
3. Ответ уходит на `POST /api/review/answer` → `review/submit.ts`. Оценка
   ставится на сервере. При сравнении корейский текст нормализуется к NFC,
   а мелкие опечатки прощаются (`review/answer.ts`). Дальше:
   - **фаза LEARNING** (заучивание): растёт серия правильных ответов подряд.
     Когда она дойдёт до цели из настроек, слово «выпускается» в повторение;
   - **фаза SCHEDULED** (повторение): FSRS (`review/session.ts`) считает
     следующую дату, а ответ пишется в `ReviewLog`.
   Эти две фазы не смешиваются: тренировочные ответы не попадают в FSRS,
   иначе он неверно оценит память.

### Сценарий 2½. Категории

- **При добавлении** (`AddWords.tsx`, переключатель «Categories»):
  - «AI sorts» — модель выбирает категорию каждому слову (по умолчанию);
  - «All into one» — все слова идут в одну выбранную категорию, и она
    запирается;
  - «I pick for each word» — сначала превью, категорию выбираешь сама.
- **Просьба прямо в тексте.** Строки без корейского над текстом (например,
  «добавь всё в категорию дорамы») уходят модели как заметка
  (`import/read.ts` → `sourceFromText`). Модель возвращает
  `requestedCategory`, и все слова идут туда, а категория запирается.
- **Замок** на /categories: слова из запертой категории никогда не двигает
  кнопка «Re-sort with AI» (`lib/words/resort.ts`). Перед запуском она
  показывает, сколько слов и сколько это будет стоить.

### Сценарий 3. Аккаунты

Первый визит: `(app)/layout.tsx` видит, что сессии нет, и показывает
`StartAnonymous.tsx`. Тот создаёт анонимного пользователя прямо в браузере,
и приложение сразу работает, только без ИИ. Когда человек регистрируется или
входит, `lib/words/merge-anonymous.ts` переносит его слова в настоящий
аккаунт. Это делается до того, как Better Auth удалит анонимного
пользователя.

### Сценарий 4. Деньги на ИИ

Каждый вызов модели проходит через две функции из `lib/ai-budget.ts`:
- `assertCanUseAi()` перед вызовом;
- `recordAiUsage()` сразу после.

1 кредит = 1 цент стоимости модели. Бесплатным пользователям дано по 50
кредитов, на всех бесплатных вместе действует дневной лимит. Почты из
`UNLIMITED_AI_EMAILS` (твоя) не ограничены. Когда кредиты кончаются, перестаёт
работать только поиск новых слов; учёба и повторение продолжают работать.

## 6. База данных — главные таблицы

Полное описание с комментариями — в `prisma/schema.prisma`.

```
User ─┬─ Entry (слово) ─── Sense (значение) ─┬─ Example (пример)
      │     │                                 └─ Card (карточка) ── ReviewLog
      │     └─ EntryCategory ── Category
      ├─ SourceMaterial (откуда слова: текст, картинка, тема)
      ├─ AiUsage (каждый вызов ИИ и его цена)
      └─ DictionaryUsage (ручные поиски в словаре за день)
```

| Таблица | Что хранит |
|---|---|
| `User` | пользователь и его настройки (цель заучивания, слов за сессию, озвучка…) |
| `Entry` | слово: написание, ханча, уровень, часть речи, `needsCheck` («словарь ещё не подтвердил») |
| `Sense` | одно значение слова: английский перевод (`translation`), твоё значение (`userMeaning`), определения |
| `Example` | пример предложения + перевод; источник: словарь, ИИ или твой текст |
| `Card` | карточка — то, что учится. Направление: RECALL (смысл → корейское слово) или RECOGNITION (наоборот). Фаза, серия ответов, все поля FSRS, `introducedAt`/`snoozedUntil` для знакомства |
| `ReviewLog` | история повторений (данные для FSRS) |
| `Category`, `EntryCategory` | категории и связь «слово ↔ категория», переключатели Learn/Review, замок `locked` (слова из такой категории не трогает перераспределение) |
| `SourceMaterial` | исходный текст импорта: откуда пришли слова |
| `AiUsage` | журнал расходов на ИИ |
| `DictionaryCache` | общий кэш ответов словаря (общий для всех, только словарные данные) |
| `GeneratedExample`, `ExampleTranslation` | общий кэш примеров и переводов, написанных ИИ |
| `Session`, `Account`, `Verification` | служебные таблицы Better Auth |

Изменить базу — значит поправить `schema.prisma`, потом выполнить
`npx prisma migrate dev --name что_поменяли`. Команда создаст миграцию
и применит её.

## 7. С чего начать чтение кода

1. `prisma/schema.prisma` — из чего состоят данные.
2. `src/app/(app)/page.tsx` — короткая серверная страница: видно, как она
   читает базу и отдаёт разметку.
3. `src/app/api/review/answer/route.ts` → `src/lib/review/submit.ts` — как
   устроен типичный API-маршрут и где живёт логика.
4. `src/components/Review.tsx` — клиентский компонент: состояние, fetch,
   разметка.
5. `src/lib/ingest/` по порядку: `extract.ts` → `analyze.ts` → `commit.ts`.

## 8. Где что менять

| Хочу… | Файл |
|---|---|
| поменять текст или вид экрана | соответствующий файл в `src/components/` |
| новая настройка | поле в `User` (`schema.prisma`) → `api/settings/route.ts` → `settings/page.tsx` → `SettingsPanel.tsx` |

| поменять, какие карточки попадают в сессию | `lib/review/queue.ts` |
| цвета и шрифты | `src/app/globals.css` |
| бесплатные кредиты и лимиты | переменные окружения (`FREE_AI_CREDITS` и др.) в Vercel |
